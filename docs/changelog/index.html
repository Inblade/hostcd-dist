Changelog

All notable changes to hostcd are documented here. This project uses date-based vMAJOR.MINOR.PATCH tags; security releases are called out explicitly.

[0.3.25] — 2026-11-22

Agents upgrade themselves — Linux and Windows — with no SSH or RDP.

Added

  • Agent self-upgrade over the pull channel. An admin clicks Upgrade agent to vX on a host (or POST /api/hosts/{name}/agent-upgrade); the agent downloads the release from the server, verifies the release manifest against a signing key compiled into the agent, checks the binary's sha256 and that it runs as the requested version, swaps itself (keeping a .bak) and restarts — via systemd on Linux, by re-running its scheduled task on Windows. Downgrades and unsigned or tampered releases are refused. A new agent that cannot reach the server within 5 minutes restores the previous binary; the host page and the audit log show the outcome. Releases now ship agent-manifest.json and its signature, and the installer stages them into -agent-dist. Agents older than v0.3.25 need one last manual upgrade. (#249)

[0.3.24] — 2026-11-22

A one-fix release for the approval gate.

Fixed

  • A commit that changes nothing for a gated app no longer needs approval. An app held at its approved revision (approval gate with self-heal, or a host over the Community cap) stayed OutOfSync after any newer commit — a revert, or a commit to another app in the same repository — until a second admin approved a no-op. When the new revision renders exactly like the approved one for a host, the host now moves to it on its own; a revision that changes the host's desired state still waits for approval. (#246)

[0.3.23] — 2026-11-21

A security and approvals release: the rest of the approval-gate review, for host apps and cluster apps alike. No new resource kinds.

Security

  • A cluster-app rollback no longer bypasses the approval gate. It applied a past revision immediately, so a single admin could change a gated cluster app without a second approval. It now waits for approval like a sync, and a sync window that blocks manual syncs blocks it too. Upgrade is recommended if you use approval gates with cluster apps. (#243)

Fixed

  • Gated cluster apps self-heal to the approved revision, as host apps do since 0.3.22: drift is restored automatically, a new revision still waits for approval and is shown OutOfSync meanwhile. (#243)
  • Approval requests can be cancelled by any admin (including the requester) from the app view or DELETE /api/apps/{name}/pending / DELETE /api/cluster-apps/{name}/pending; cancellations are audited. (#243)
  • Requests show what they would apply — the revision, and whether it is a rollback. A request made for a branch head that has since moved on is marked outdated and can no longer be approved, only cancelled. (#243)
  • A request with nothing to do is refused (every target already runs that revision with no drift), and an approved rollback of a host app now runs and is recorded as a rollback rather than a plain sync. (#243)

Changed

  • The app view explains a gated automated policy as "Revision changes require approval. Drift from the last approved revision is self-healed automatically." A sync window that blocks automated sync is a change freeze and pauses self-heal too; this is now documented. (#243)

[0.3.22] — 2026-11-21

A small fix release: approval gates and self-heal now work together. No new resource kinds or features.

Fixed

  • Self-heal works under an approval gate. An app in a project that requires approval, with automated sync and self-heal on, now restores the revision a host already runs (a stopped service, a hand-edited file) without a second admin. Restoring is not a new change, so only moving to a new revision still waits for approval. Previously the gate turned self-heal off entirely, while the UI still showed "Auto, self-heal". (#240)
  • The UI shows when an approval gate narrows the automated policy ("approval required"), and a host holding the approved revision while a newer one waits is reported OutOfSync with the reason instead of Synced. (#240)
  • Stale approval requests are dismissed automatically. A pending sync whose revision every target host already runs, with no drift, is cleared and recorded in the audit log, instead of waiting for a second admin forever. (#240)
  • Hosts over the Community host cap self-heal again. A frozen host keeps restoring the revision it last accepted, as documented; it never actually did. (#240)

[0.3.21] — 2026-11-16

A security release. The fixes from the 2026-11 security review that had landed on main are now shipped; no new resource kinds or features.

Security

  • The standalone hostcd server authenticates /status, /metrics and /sync. When a sync token is configured these endpoints are no longer open; without one the server binds loopback-only by default and logs a warning if it is placed on a non-loopback address unauthenticated. (#236)
  • Server-side request forgery via Team webhooks is blocked at dial time. Webhook delivery now refuses loopback, link-local, the cloud metadata address (169.254.169.254) and multicast targets — covering redirects and DNS rebinding — while ordinary private ranges stay allowed for on-prem endpoints. The server also gained idle and header-size limits. (#234)
  • golang.org/x/net upgraded to 0.62.0 to pick up the fix for CVE-2026-78661. (#229)

Changed

  • Internal hardening, no behaviour change. golangci-lint (with gosec) now runs in CI and make lint; a scheduled gitleaks / trivy / govulncheck scan runs every two days and on each release tag; the port-forward proxy moved off the deprecated Director API; and the largest server files were split for maintainability. (#219, #221, #223, #225, #227, #231, #232)

[0.3.20] — 2026-11-12

A small maintenance release: the fixes accumulated since v0.3.19, no new resource kinds or features.

Added

  • "Check for updates" button in Settings → Software updates. It forces a fresh check against the release channel and shows "You're up to date" when there is nothing new, or offers the update (one-click when the server has the updater configured) — so an operator no longer has to wait out the background poll or rely on the passive banner.

Fixed

  • Settings were stale right after a form login. /api/settings is now refetched immediately after login (as it already was on a page reload), so the license card, the nav update banner and the installed-version row render correctly instead of appearing empty until the next reload.

Changed

  • Honest status on read-only instances. A read-only server (the public demo) no longer advertises Team-trial write permissions it cannot exercise: the UI/API entitlement view reports the write-capable permissions as unavailable and flags readOnly, while enforcement is unchanged (read-only is already enforced at the HTTP layer). The Recovery "Backup & restore" card labels the UI export/import as config export/import and points at reliability/pilot-restore-drill.sh for the actual data-dir disaster-recovery rehearsal.
  • The release publishes the site hands-free. The docs-sync PR to the public hostcd-dist site now auto-merges once its consistency check passes, instead of waiting for a manual merge every release.

Reliability

  • Real-data restore drill for the live pilot (reliability/pilot-restore-drill.sh
    • PILOT-RESTORE-REPORT.md): a non-destructive drill that backs up the live data dir, restores it onto a throwaway instance, confirms the real applications and hosts recover and the sealed secrets decrypt, and checks that a mismatched bootstrap.key fails closed — the disaster-recovery evidence on real state, not just the synthetic CI drill.

[0.3.19] — 2026-11-11

Added

  • nvidia_gpu resource kind — converge a GPU bare-metal host to the full NVIDIA monitoring stack from Git in one declaration: the datacenter driver (which provides nvidia-smi), the DCGM host engine (nvidia-dcgm) and the DCGM Prometheus exporter (nvidia-dcgm-exporter, serving /metrics on :9400). The package names are identical on apt and dnf, so the same declaration works on Ubuntu/Debian and RHEL/Rocky; pair it with a CUDA apt_repository / yum_repository for the packages to install from, then point Prometheus at <host>:9400. Knobs: cuda_major (default "12"), driver (default on), state present|absent. Health reports Degraded if the DCGM engine or exporter is down, so a crashlooping unit is not reported healthy. See examples/repo/groups/gpu/nvidia.yaml.

Changed

  • The public site now stays in lockstep with releases automatically: the hostcd.dev changelog page is generated from this file and the pinned install version on the landing and README is bumped on every release, so neither drifts from the shipped version again.

[0.3.18] — 2026-11-11

Added

  • Read-only mode (-read-only) — the server refuses every mutating request with a clean JSON 403 and advertises readOnly:true in the session, while the UI gates its write controls (the "New folder" button and other mutations are hidden for a read-only session). The agent poll is a token-authed POST outside the session-auth wrapper, so agents keep reconciling. Two companion flags shape the read-only banner: -read-only-note sets the reset-cadence sentence and -read-only-link renders a "Learn more →" link. This is what powers the public anonymous demo.

Security

  • Toolchain bumped to Go 1.26.11 — picks up the net/http fix for GO-2026-6859.
  • Fresh installs authenticate /metrics by default — install.sh now generates a HOSTCD_METRICS_TOKEN on first install, so a new server requires a bearer token to scrape metrics (remove the line in server.env to open it on a trusted network). A server started manually without the token still leaves /metrics open, as documented in the threat model.
  • The release fails if a required artifact is missing — including the Windows agent — so sha256sum -c can no longer verify a release green while an artifact that silently failed to build is simply absent from SHA256SUMS.

Fixed

  • The modal/drawer scrim is now a neutral black, so it visibly dims the content behind it on the dark theme (it previously matched the dark page background and dimmed nothing).
  • Truncated commit messages in the UI now show the full message in a tooltip.

Docs

  • Backup/restore runbook with explicit RPO/RTO in the operations guide; an RDP runbook for moving an SSH-less Windows agent to a per-host token; a top-level ROADMAP.md (now/next/later); a repo CLAUDE.md; and a roadmap-wording fix (approval gates / notifications / audit export are Team, not Enterprise).

[0.3.17] — 2026-11-10

Added

  • Mint a per-host agent token for an existing host — POST /api/hosts/{name}/token (admin-only, audited). Per-host tokens were previously minted only by install-over-SSH, so a host with no SSH path (a Windows agent, or an air-gapped host) could not be moved off the shared enrolment token. The new endpoint mints a fresh per-host token, clears any revocation, persists the new digest before returning it, and returns the plaintext once — paste it into the agent's config and restart. It also rotates an existing per-host token. Minting invalidates the host's previous token immediately, so the agent is briefly offline until it is reconfigured with the new token.

[0.3.16] — 2026-11-09 — reliability & HA hardening

Security

  • Fixed a reload-path panic (DoS): a config reload that produced a nil result set could panic the server; reload is now nil-safe.
  • /metrics no longer holds a lock across network I/O — the snapshot is taken under the lock and written without it, closing a lock-contention/DoS window. (Operators on a public address should still set -metrics-token; /metrics is unauthenticated by default.)

Changed (HA — Enterprise preview)

  • Leader election now demotes fail-closed on a failed lease acquire/renew instead of keeping leadership until a later success (removes an unbounded split-brain window); pgElector.release errors are surfaced, not swallowed.
  • A standby reloads its cache after a LISTEN reconnect, so a NOTIFY missed during a connection outage is still caught.
  • Write-forwarding to the leader trusts system roots plus a configurable -peer-ca / HOSTCD_PEER_CA bundle (fixes self-signed peer TLS; never skips verification, fails closed) and retries once against a fresh leader URL when nothing has been written yet; an undeliverable forward returns 503 + Retry-After rather than a hard 502.
  • HA remains an Enterprise preview pending a multi-day two-node soak.

Fixed

  • The server refuses a server-side install from a stale -agent-dist (prevents a silent agent downgrade) and warns at startup on a version mismatch.

Added

  • deploy/install.sh can auto-populate -agent-dist with cosign/SHA256SUMS- verified agents in lockstep with the server version (opt-in via HOSTCD_AGENT_DIST; platforms via HOSTCD_AGENT_DIST_PLATFORMS), re-staged on every install/upgrade. The host drawer now shows server / hosted-dist / installed agent versions and flags drift.

Internal

  • Test coverage for Package/Service.Apply, engine Run/Trigger/Snapshot, the git source, and license removal; an HA fault suite (partition fail-closed demote, LISTEN-reconnect re-signal). CI now fails (not skips) Postgres tests when its DSN is missing, adds an embedded-key SSO end-to-end check, and the RUSTSEC-2024-0429 glib ignore self-expires once glib reaches ≥ 0.20.

[0.3.15] — 2026-11-08 — security release

Security

  • High: fixed an app-destination label-scope bypass — a per-host agent token could read another scope's secret-bearing manifest by reporting crafted labels. Destination matching now uses admin-assigned labels only (frozen after enrolment; clears persist across restart/HA). Upgrade is recommended.
  • Medium: GET /api/audit is now admin-only (was readable by scoped viewers).
  • Low: GET /api/events (SSE) no longer leaks out-of-scope resource names to scoped viewers.
  • Hardening: resource exec sinks reject option-injection in package/service/user/group names.
  • Desktop: tokio → 1.54.1; cargo-audit now runs in required CI.

Added

  • Windows agent hostcd-agent-windows-amd64.exe published in releases (late beta; package/file/service). See docs/WINDOWS.md.
  • UI: view and edit a host's admin-assigned targeting labels.

Fixed

  • Documentation consistency (pricing/trial wording); self-contained public release notes.
