Changelog — issues & fixes

This is the public record of every hostcd release: what was found and how it was fixed, from the first public release onward. The core source is not public yet, so this page — alongside the signed GitHub Releases — is how you can see the track record before trusting the tool with root on your servers.

Every release ships a SHA256SUMS signed with keyless cosign (GitHub OIDC → Fulcio → Rekor; no private key in CI) and an SBOM. The public mirror is not re-signed, so artifacts stay independently verifiable against the source workflow's identity — see verify-before-install. Dates are UTC.

In progress

  • Nothing unreleased right now — see the roadmap for what is planned next.

v0.3.17 — 2026-11-10 · SSH-less enrollment

  • Mint a per-host agent token for an existing host. A new admin-only, audited endpoint mints (or rotates) a per-host agent token for a host with no SSH path — a Windows agent, or an air-gapped host — so it can be moved off the shared enrollment token and that shared token revoked. The new token is persisted before it is returned and shown once; minting invalidates the host's previous token immediately, so the agent is briefly offline until it is reconfigured with the new token.

v0.3.16 — 2026-11-09 · reliability & HA hardening

  • Fixed a reload-path crash (denial of service). A configuration reload that produced an empty result set could panic the server; reload is now nil-safe.
  • /metrics no longer holds a lock across network I/O, closing a lock-contention/DoS window. On an untrusted network, protect the endpoint with -metrics-token (it is unauthenticated by default).
  • HA: no more split-brain window on a lease fault. A leader now demotes fail-closed on a failed lease acquire/renew instead of holding leadership until a later success. In-flight leader work is cancelled the moment leadership is lost (a leader context), so a demoted node cannot keep applying to clusters, committing state, or emitting notifications as an ex-leader.
  • HA: standby catches up after a database blip. A standby reloads its cache after a LISTEN reconnect, so a change committed during a brief outage is no longer missed. Write-forwarding to the leader trusts a configurable peer CA (-peer-ca) for self-signed peer TLS and fails closed, never skipping verification.
  • Agent-version safety. The server refuses a server-side install that would downgrade a host's agent (stale -agent-dist guard), the installer can auto-populate the agent distribution in lockstep with the server version, and the host drawer shows server / hosted / installed agent versions and flags drift.
  • Closed test gaps (resource, engine, git source, license removal) and added an SSO embedded-key end-to-end check in CI. Docs: "active-active HA" clarified to active-active reads with a single elected writer.

v0.3.15 — 2026-11-08 · security release

  • High — label-scope bypass fixed. A per-host agent token could read another scope's secret-bearing manifest by reporting crafted labels. Destination matching now uses admin-assigned labels only, frozen after enrolment and persisted across restart and HA, so a compromised host token cannot relabel itself into another scope. Upgrading is recommended.
  • Medium — GET /api/audit is now admin-only (was readable by scoped viewers).
  • Low — GET /api/events (SSE) no longer leaks out-of-scope resource names to scoped viewers.
  • Resource exec sinks reject option-injection in package / service / user / group names.
  • Desktop: tokio → 1.54.1 and cargo-audit now runs in required CI.
  • Windows agent is published in releases (late beta) with a Windows install guide.

v0.3.14 — 2026-11-07

  • Dependency security: bumped golang.org/x/oauth2 to v0.27.0 (CVE-2025-22868).
  • Documentation reconciled (monthly pricing, trial window, lapse behaviour, feature ownership) with a consistency guard in CI; public release notes are now self-contained (private source links stripped).

v0.3.13 — 2026-11-06

  • Fixed a misleading package error. When an apt-get update during a package apply failed (for example on an end-of-life release whose repositories moved), the real error was swallowed and surfaced as "unable to locate package". Both errors are now shown, with an apt-sources hint.
  • UI: an automated-only application showed "No sync yet"; it now shows the latest sync from history.

v0.3.12 — 2026-11-06

  • UX: noisy login events collapse behind a toggle in Activity; the sidebar shows a loading placeholder instead of 0/0 before the first load.

v0.3.11 — 2026-11-06

  • Self-update hardened fail-closed. The opt-in one-click updater now requires cosign (no HTTPS-only fallback) and refuses to proceed if latest cannot be resolved to a concrete release tag — it never follows a moving target.

v0.3.10 — 2026-11-05

  • Fixed a self-update helper parsing failure (a shell exit-127 on the installer exec line).

v0.3.9 — 2026-11-05

  • Fixed one-click self-update. The update is now triggered through a root systemd .path unit (the server runs with NoNewPrivileges, which blocked the previous sudo path), and the helper no longer overwrites itself mid-run.

v0.3.8 — 2026-11-05

  • Self-update verifies before running as root. The helper now checks the installer's own cosign provenance and checksum against the signed SHA256SUMS before executing it, and pins one resolved release tag. The real changelog is mirrored into the public release notes.

v0.3.7 — 2026-11-05

  • The self-update capability is surfaced on the API so the "Update now" button renders when an update is available.

v0.3.6 — 2026-11-05

  • The running version is shown in the sidebar; an opt-in one-click update button was added.

v0.3.5 — 2026-11-05

  • Fixed a silent agent lockout. Install-over-SSH enabled but did not restart an already-running agent, so after a token rotation a host could keep using its old token and drop offline (401) on a later server restart. The agent is now restarted on install.

v0.3.4 — 2026-11-05

  • Added an update checker and in-app "what's new"; fixed an application-view crash when an app matched zero hosts; status highlighting in the UI.

v0.3.2 — 2026-11-03

  • Release-pipeline and packaging hardening following the public launch (signed-tag release authorization, reproducible signed artifacts), validated with live installs on fresh VMs.

v0.3.1 — 2026-11-03

  • Packaging and install-path fixes following the first public release.

v0.3.0 — 2026-11-03 · first public release

  • First public install channel: signed binaries with SHA256SUMS, keyless cosign provenance and an SBOM. Outbound-only pull agent (nothing listens on a managed host), git-driven drift detection, preview, sync, rollback and an audit trail for plain Linux servers — without Kubernetes.
