# Security

This document is the security reference for hostcd: how to report a
vulnerability, the threat model it is built against, why it uses a pull-based
root agent instead of agentless SSH, and the risks you accept when you run it.

For the mechanism-by-mechanism detail behind every claim here, see the
[**Security model**](README.md#security-model) section of the README — this file
is the map, that section is the territory.

## Reporting a vulnerability

**Do not open a public issue for a security problem.** Report it privately:

- GitHub: use **Security → Report a vulnerability** (private advisory) on this
  repository, or
- Email: send to the maintainer address listed on the repository owner's GitHub
  profile, with `hostcd security` in the subject.

Please include a description, the version or commit, and the smallest steps that
reproduce it. We aim to acknowledge within **3 business days** and to agree a
fix-and-disclosure timeline with you from there. We will credit you in the
advisory unless you ask us not to.

Out of scope: findings that require an attacker who already has root on the
server host or on a managed host (see *Trust boundaries* — those are inside the
boundary by design), missing hardening on a plaintext-HTTP deployment you chose
to run (hostcd warns against it), and reports generated by automated scanners
with no demonstrated impact.

## Supported versions

hostcd is pre-1.0 and ships from `main`. Security fixes land on `main` and in the
next tagged release; there is no back-port stream for older tags yet. Run a
recent release. This policy will firm up at 1.0.

## Version compatibility and EOL

**Agent ↔ server wire protocol.** The agent and server negotiate a versioned
wire protocol (`spec.ProtocolVersion`), so the two do not have to be upgraded in
lockstep:

- The server advertises its protocol and the oldest it still serves on every
  poll response (and in the `X-Hostcd-Server-Version` / `X-Hostcd-Min-Protocol`
  headers). An agent whose protocol differs logs a one-time warning but keeps
  working while the server still supports it.
- A server refuses an agent older than its minimum with **`426 Upgrade
  Required`** rather than mis-serving it desired state. `-min-agent-protocol`
  raises that floor to force a fleet-wide agent upgrade when a change is
  incompatible.
- **Upgrade order:** upgrade the **server first**, then roll the agents. A newer
  agent against an older server is not a supported direction.

**Recommended practice.** Keep agents within one minor of the server, and roll
the fleet promptly after a server upgrade. The protocol version is bumped only on
an incompatible change to the poll contract; a routine release does not change
it, so most upgrades need no coordinated agent push.

**End of life.** Until 1.0, only the latest release is supported; older tags get
no fixes. At 1.0 we will publish a concrete support window (how long a minor
receives security fixes) and a minimum-supported-agent policy here. If you need a
supported older line before then, pin a release and plan to move forward rather
than expecting a back-port.

## What hostcd is

hostcd keeps a fleet of Linux hosts aligned with a git repository. A single
**server** renders the desired state per host from git; an **agent** on each host
dials out, pulls its own manifest, and reconciles it. Nothing listens on a
managed host. See the README for the full picture.

## Assets worth protecting

1. **The git repository.** It is the source of truth. Write access to a folder
   the fleet tracks is, in effect, **root on every host that folder targets** —
   hostcd will faithfully apply whatever git says.
2. **Rendered manifests**, which may embed **decrypted secrets** (file contents,
   env values) on their way to a specific host.
3. **Sealed credentials at rest on the server**: SSH private keys used for the
   one-time install/provision, admin kubeconfigs, webhook signing secrets, the
   session-signing key, and the SAML SP key. All are sealed with `bootstrap.key`
   (optionally wrapped by Vault Transit).
4. **Operator identities**: the admin/viewer accounts and their sessions.
5. **Agent tokens**: the per-host bearer tokens that authorize a host to pull its
   manifest.

## Trust boundaries

```
  ┌─────────────┐  signed/reviewed pushes   ┌──────────────────────┐
  │     Git     │ ────────────────────────► │     hostcd-server     │
  │ (GitLab/…)  │   (webhook, outbound)     │  renders per-host     │
  └─────────────┘                           │  state; holds sealed  │
                                            │  creds; operator UI   │
        operators ──login(HTTPS)──────────► └──────────┬───────────┘
                                                        │  outbound only
                        hosts dial OUT, long-poll HTTPS │  (no inbound to hosts)
                              ┌──────────────┬──────────┴───┬──────────────┐
                         hostcd-agent   hostcd-agent   hostcd-agent   hostcd-agent
                          (root)         (root)         (root)         (root)
```

- **Git → server** is a trust relationship, not a boundary you can police from
  inside hostcd. hostcd verifies commit signatures when you configure
  `allowed_signers`, but it cannot un-apply a malicious commit that a valid
  signer pushed. **Protecting the repo is your job**: branch protection, required
  reviews, CODEOWNERS, signed-commit verification.
- **Server → host** is **one-directional at runtime**: hosts never accept
  connections; the agent only dials out and polls. The single exception is the
  one-time bootstrap (SSH install / kubeadm provisioning), where the server
  reaches *into* a host over an existing SSH channel — after that the link is
  pull-only again.
- **Inside the server host is inside the boundary.** Root on the server can read
  `bootstrap.key` and therefore every sealed credential, and can read rendered
  manifests. Vault Transit wrapping raises the bar for data *at rest* (backups,
  snapshots, disk theft) but a compromised *running* server still decrypts —
  inherent to any KMS envelope. **Treat the server host as a crown-jewel box.**
- **An agent trusts the server's manifests.** A host applies what the server
  renders for it. A compromised server is therefore a fleet-wide compromise; this
  is the same concentration of trust Argo CD has over a cluster, and the reason
  the server host and the git repo are the two things to guard hardest.

## Adversaries and how hostcd answers them

| Adversary | What hostcd does |
|---|---|
| **Network attacker between agent and server** | Install refuses non-`https` (except loopback); agent verifies the server cert; optional `-agent-mtls` means a leaked token alone no longer authorizes a poll. |
| **Someone who steals one host's agent token** | Per-host tokens: a token is pinned to its host and cannot pull another host's manifest (so it can't harvest the fleet's secrets). Revoke drops the host's digest and refuses every token for it at once. |
| **Machine-in-the-middle on the bootstrap SSH** | Host key pinned on first use (TOFU); a changed key is refused. |
| **Brute-force / credential spray on the operator login** | ~700 ms delay per failure, per-account lockout (5/15 min) *and* per-client-address lockout (20/window), dummy-hash compare so timing doesn't reveal account existence. |
| **Stolen or stale operator session** | Stateless signed cookies with a per-user version; bump it (sign-out, password reset) to kill all of a user's sessions at once. OIDC/SAML back-channel/single logout tie session life to the IdP. |
| **Low-privilege operator overreach** | admin/viewer roles enforced server-side (not just hidden in UI); viewers can be scoped to clusters, app folders and host-label selectors; the last admin can't be removed. |
| **Resource-exhaustion / slowloris** | 10 s header-read timeout, 1 MB API body cap, 32 MB agent-poll cap. (No blanket request timeout — long-polls and SSE are long-lived by design; rate-limit in the proxy.) |
| **Malicious repo content** | Trees extracted without symlinks; `source:` and app paths cannot leave their folder; git args cannot start with `-`; `sensitive: true` files never leave the host. |
| **Secrets leaking via bulk import** | The Ansible-inventory importer never stores secret-looking vars and promotes a non-connection var to a label only through an explicit `labels=` allow-list. |

## Why a root agent, not agentless SSH

This is the first question most ops teams ask, so here is the reasoning in full.

**hostcd runs a small agent on each host, as root, that only dials out.** It does
*not* keep SSH keys to your fleet and push changes in. That is a deliberate trade,
and the opposite of how Ansible works.

**Why dial-out (pull) instead of the server pushing over SSH:**

- **No inbound surface on the fleet.** Nothing listens on a managed host — no SSH
  port that has to be open to the control plane, no inbound firewall rule, no
  bastion to reach private hosts. A host behind NAT or in a locked-down VPC still
  reconciles, because *it* opens the connection outward. This shrinks the fleet's
  attack surface to zero inbound.
- **No fleet-wide key on the server.** An agentless push tool must hold an SSH
  credential that is root on every host; stealing it is stealing the fleet.
  hostcd's server uses SSH only for the *one-time* bootstrap (and cluster
  provisioning); runtime reconciliation uses none. Be precise about what this
  does and does not mean: a key you supply for a bootstrap is **kept, sealed at
  rest** (AES-GCM under `bootstrap.key`), so a later re-install or cluster
  operation does not have to ask for it again — it is **not** wiped once the
  agent is running. It stays until you **forget the host/cluster**, which deletes
  the sealed key along with the record. So the server may hold per-host SSH keys
  at rest, but no *single* credential is root on the whole fleet, and the
  steady-state pull path needs no SSH key at all. The per-host agent token that
  authorizes runtime polling is scoped to one host and revocable.
- **Continuous reconciliation, not a cron of pushes.** A pull agent closes drift
  as it happens and reports state back; a push model only converges when someone
  runs the playbook. This is the GitOps property — the same reason Argo CD pulls.
- **Blast-radius containment.** A compromised agent token leaks one host's
  manifest, not a key to all of them.

**What you pay for it — stated honestly:**

- **The agent is root.** It installs packages, writes files anywhere, manages
  services — it needs root to do the job, exactly as `ansible-pull` run from cron
  or a configuration daemon would. The agent is a small Go binary with no inbound
  listener, which is the surface you are trusting. The systemd unit it installs is
  hardened to shrink that surface: `ProtectKernelModules`, `ProtectClock`,
  `LockPersonality`, `RestrictRealtime`, `PrivateTmp`, and a `0700` state
  directory.
- **Trust moves to the server and the repo.** Instead of trusting an SSH key
  store, you trust that the server renders only what git says and that git is
  protected. That is why this document names the server host and the repo as the
  two assets to guard hardest.
- **You run one more component.** The server is a process you host, update and
  back up. Agentless tools have no such component (they trade it for the inbound
  SSH surface and the fleet-wide key above).

If your constraint is "no new daemon on the hosts, ever," hostcd is not the tool
for you — reach for `ansible-pull` on a timer and accept the inbound/again-later
trade. If your constraint is "no inbound access to the fleet and no standing
fleet-wide credential," that is exactly what the agent buys you.

## Known limitations and residual risk

These are real and intentional-for-now, listed so you can decide with eyes open:

- **Root on the server reads all sealed secrets.** `bootstrap.key` lives (0600) in
  the data dir by default. Vault Transit wrapping protects data at rest but not a
  live compromised server. Lock down the server host accordingly.
- **A compromised server is a fleet compromise.** Agents apply what it renders.
  There is no second signer between the server and a host for host manifests.
- **The git push token is powerful.** It is effectively root on every targeted
  host. Signed-commit verification reduces — but does not eliminate — the value of
  a stolen push token; branch protection and review are the real controls.
- **Plaintext HTTP is unsafe and only warned about, not blocked** on a
  non-loopback listener without `-tls-cert`. Terminate TLS (direct or via a
  proxy). Install over SSH is refused without https precisely because of this.
- **`/metrics` is public by default.** Set `HOSTCD_METRICS_TOKEN` if the endpoint
  is reachable by anyone who shouldn't see fleet topology.
- **Sealing-key rotation is a single-node, cluster-stopped operation.** Under
  `-ha` it is refused; rotate with the cluster stopped.
- **Auth can be turned off.** `-insecure-no-auth`, or an empty
  `HOSTCD_ADMIN_PASSWORD`, disables operator login and makes every caller an
  admin. It exists for demos and loopback-only use — never expose such an
  instance to a network.
- **No per-release security back-ports yet** (pre-1.0; see *Supported versions*).

## Operator hardening checklist

- [ ] Server reachable only over **HTTPS** (`-tls-cert`/`-tls-key` or a TLS proxy).
- [ ] Repo has **branch protection + required review**; `allowed_signers`
      configured for **signed-commit verification**.
- [ ] `bootstrap.key` is `0600`, backed up **alongside** `state.json`, and — for
      anything beyond a single box — **wrapped with Vault Transit**
      (`-vault-addr`).
- [ ] The **server host is treated as crown-jewels**: minimal access, patched,
      monitored.
- [ ] Per-host agent tokens in use; the shared `HOSTCD_AGENT_TOKEN` left **unset**
      once hand-installed agents are gone.
- [ ] `-agent-mtls` enabled if a leaked token must not be enough on its own.
- [ ] Operators use **SSO** (OIDC/SAML) and least-privilege **viewer scopes**
      where possible; `HOSTCD_ADMIN_PASSWORD` strong and rotated.
- [ ] Behind a proxy, `-trust-proxy` set so lockouts key on the real client IP,
      and a **request-rate limit** configured in that proxy.
- [ ] `HOSTCD_METRICS_TOKEN` set if `/metrics` is exposed.
- [ ] The **audit trail** (`GET /api/audit`) is shipped somewhere durable.
